# Docklane v0.3 开发计划

依据根目录 PRD v0.3 和本次确认范围执行。Docker Engine 是实时状态权威；首版单本机 Host；默认不损坏已有资源。

## 已确认范围

- 首版包含容器原地配置更新、独立容器重建与失败回退、Compose 无损导入、镜像/网络/存储管理。
- 本地 Restic 文件级和停机备份、Cron 策略、离线仓库恢复；数据库逻辑导出后续交付。
- 二进制模式经显式授权支持 daemon 配置写入、重启及回退；Docker 模式只诊断和手动指引，Host Helper 后续交付。
- Ubuntu 24.04、Debian 12/13，amd64/arm64；Docker Engine 28/29；Compose v2。
- P1 通知及远程备份、P2 多机/RBAC 不在首版。

## 公共契约

REST `/api/v1`；主机资源统一 `host_id=local`；SSE `/api/v1/events`；WebSocket 交互终端。SQLite 保存管理元数据，使用显式 SQL 和版本化迁移。长任务返回任务 ID；高危操作必须服务端预检、展示差异、确认、重新校验对象版本、执行、验证、审计。API 404 不回退为 SPA。

备份容器只挂载指定源和仓库，不挂 Docker Socket/宿主机根目录。Bind 路径必须显式授权；不支持的 Driver 禁用。停机覆盖全部已知写入容器，持久化原运行状态，在失败/取消/重启后尽力补偿。恢复不自动覆盖数据。重建保留旧容器到新容器验证完成，无法可靠表达的配置拒绝；配置回退不撤销数据写入。

调度 `(policy_id, scheduled_at_utc)` 唯一，同策略不并发；不补跑离线期间计划。快照提交、校验和运行状态恢复成功后才做保留清理。结构检查不等于数据读取校验。manifest 随快照加密，不依赖原 SQLite。

## 可独立验证的任务

下列清单是后续实现与修改的工作分解。代码实现、自动化覆盖和发布验收分别记录；只有相关验收证据齐全才能关闭阶段。当前执行结果见验收矩阵与验证报告。

### S0：工程基础与验收契约

1. 初始化 Git、Go、前端工程；目录使用 `cmd`、`internal`、`web`、`deployments`、`scripts`、`docs`。
2. 锁定 Go、Node、pnpm、Docker SDK、Compose、Restic 及依赖锁文件；建立开发、构建、测试、静态检查和 Linux 集成入口。
3. 单进程嵌入前端，提供 REST、SSE、WebSocket；区分页面路由和 API 404。
4. 固化错误码、任务五种状态、配置版本、能力矩阵及 45 AC / 10 发布场景；准备隔离 Linux 测试数据。

完成标准：前端可嵌入 Go；页面/API 路由正确；CI 配置可执行基础检查。依据 PRD 10.1、10.2、10.5。

### S1：初始化、认证、主机能力与工作台

1. 实现配置检查、私有数据目录、SQLite 显式 SQL 迁移及启动生命周期。
2. 首次初始化互斥、管理员创建、密码哈希、会话、退出、CSRF、登录限流。
3. 敏感配置加密；主密钥独立保存、限制文件权限、提供离线保管说明。
4. Docker SDK API 版本协商、连接检测、断连诊断与重连；工作台、设置和能力页面。

完成标准：仅初始化一次；未认证不能管理；Docker 不可用仍可登录；统计与 Engine 一致且刷新只读。对应 DASH-01～03、SYS-01～04、ARCH-04～06。

### S2：任务、审计与实时通道

1. 持久任务队列、阶段/进度/日志、超时、幂等键、重试和安全取消。
2. 任务列表/详情/错误、审计、SSE 订阅/补取/重连及日志脱敏。
3. 冲突资源、同一仓库及同策略互斥；中断识别、必要补偿和调度恢复门禁。

完成标准：五种任务状态；历史在重启后保留；不安全续跑的任务失败并说明恢复步骤，禁止统一重新入队。对应 TASK-01～03。

### S3：容器、镜像、网络与存储

1. 资源列表/详情/分页/筛选/关联、容器启停重启、日志 Tail/时间戳/跟踪、TTY 与 Stats。
2. 原地配置更新、独立容器重建预览/重验/结果验证/失败回退；Compose 容器引导至项目。
3. 镜像拉取进度/Digest/引用检查/导入导出、加密仓库凭据；网络与卷管理。
4. Volume/Bind Mount 展示，显式授权路径上的异步限流大小扫描。

重建先保留旧配置与运行状态，再停止旧容器、创建并验证新容器；失败恢复旧名称、连接及原运行状态。无法可靠表达的特殊配置预检拒绝。删除默认保留卷与宿主数据；没有运行引用不等于可自动删卷。终端断开释放连接。

完成标准：发现 CLI/第三方资源；操作后重新读取 Engine；满足 CTR-01～07、IMG-01～02、STO-01～03、ARCH-08。

### S4：Compose 项目管理

1. 标签发现、文件访问/映射检查、关联导入及项目索引。
2. 保留多文件顺序、工作目录、env_file、profiles、插值上下文；源文件缺失时生成“待验证”候选 YAML。
3. 文件版本与变更检测、编辑、部署历史；通过受控参数执行 Compose，不拼接 Shell。
4. 部署前校验，预览服务、网络、卷及影响范围；源文件变化后重新预览。

完成标准：导入不部署，容器 ID/端口/挂载不变；无法访问文件时解释原因。对应 CMP-01～03。

### S5：Restic 仓库与定时备份

1. 创建/导入本地仓库、口令加密与离线材料导出；容器/Compose/卷/目录策略及手动执行。
2. Cron/IANA 时区、排除规则、重试、保留；空间/权限/路径/递归检查。
3. 配置、挂载、镜像与必要文件元数据写入独立版本的加密 manifest。
4. 停机范围枚举全部共享写入者，确认后冻结授权；持久化原状态，在成功/失败/取消/重启后恢复原本运行的容器。
5. 调度 UTC 实例唯一去重，不补跑停机期间计划，记录遗漏；成功提交并校验且状态恢复后执行保留清理。

Docker 模式使用指定卷的临时备份容器，源只读，不挂宿主根目录或 Socket；Bind/Compose/仓库均需明确映射授权，不支持的 Driver 禁用。无一致性保证的文件备份必须提示，不能冒充数据库一致性。完整数据校验使用 `check --read-data`，普通 `check` 只是结构检查。

完成标准：满足 BKP-01～05、07；恢复证据在 S6 闭环。

### S6：恢复向导与灾难恢复

1. 浏览快照、读取 manifest、恢复预检、覆盖范围预览、确认及任务进度。
2. 默认新目录；原位覆盖检查写入者、停机并二次确认；验证内容、类型、权限、UID/GID 和必要元数据。
3. 选择性重建容器/Compose，预先处理镜像/端口/网络/路径冲突，单独显示服务健康结果。
4. 全新安装仅通过仓库和离线口令发现快照、读取 manifest、恢复，禁止依赖原 SQLite 索引。

完成标准：文件验证与服务健康分别报告，不以退出码替代验证；满足 BKP-01、04、06 和发布场景 6～9。

### S7：镜像加速诊断与宿主机操作

1. 分别诊断网络、Registry API、实际镜像拉取，提供建议及手动向导。
2. 仅二进制模式且显式授权时读取/合并/校验 daemon 配置；预览差异、备份和原子写入。
3. 确认后重启，限时等待并验证；持久化变更阶段；失败恢复文件并尝试恢复服务，避免重启后重复执行。

完成标准：保留未修改字段；预告影响；容忍有界暂时断连；无授权 API 拒绝并审计；Docker 模式仅诊断和指引。对应 IMG-03～05、SYS-03～04 及场景 4、5、10。

### S8：发布、升级与运维

1. amd64/arm64 镜像、Linux 二进制、SHA256SUMS、systemd 文件；镜像包含锁定 Compose/Restic，二进制安装检查外部工具。
2. 安装/启动/升级/卸载/反代/映射/最小授权文档；升级前停服务备份数据库、配置、密钥及原程序。
3. 迁移失败停止升级并提供回退步骤；卸载保留数据与备份；密钥保管、仓库导入、故障处理、灾难恢复手册。
4. Ubuntu 24.04、Debian 12/13 × amd64/arm64 × Docker/二进制验收，Engine 28/29 实测；安装不得停止或重建已有资源。

完成标准：两种方式同一页面与 API，运行不依赖 Node/Nginx/MySQL；升级保留用户/策略/仓库/历史。对应 ARCH-01～03、09～10 及全部适用发布场景。

## 验证与推进

按 S0→S8 推进；契约稳定后独立模块可并行。每阶段记录验收状态和证据，执行 Go tests/vet/race、前端类型/测试/构建和适用 Linux 集成测试。未运行的检查不标记通过。45 AC 中 44 首版适用，AC-ARCH-07 延后；10 发布场景均需真实证据。
